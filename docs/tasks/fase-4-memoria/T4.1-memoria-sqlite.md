# T4.1: Memoria en SQLite

- **Fase:** 4
- **Estado:** Pendiente
- **Depende de:** T3.2

## Objetivo

Las conversaciones se guardan en SQLite con una etiqueta de sensibilidad por mensaje y se pueden recuperar entre ejecuciones.

## Contexto mínimo

- **Base:** `.harness/memory.db` con `sqlite3` de la biblioteca estándar. Sin ORM.
- **Esquema mínimo:**
  - `conversations(id, title, created_at, updated_at)`
  - `messages(id, conversation_id, role, content, sensitivity, created_at)`. `sensitivity` es `private | public`, la del `RunContext` al terminar el turno (un turno contaminado se guarda `private`).
- **Migraciones:** una tabla `schema_version` y migraciones como funciones numeradas. Nada más.
- **API (`MemoryStore`):** `new_conversation()`, `append(conv_id, message, sensitivity)`, `history(conv_id, limit)`, `list_conversations(limit)`. La conexión se abre en `build_app`, no al importar.
- **Enganche con privacidad:** cargar mensajes `private` en un run llama a `RunContext.taint("memory")` (punto preparado en T3.2).

## Alcance

**Incluye:** `harness.memory` (store, esquema, migración inicial).

**Fuera de alcance:** armado de contexto y comandos de la CLI (T4.2). Memoria a largo plazo, resúmenes, embeddings.
