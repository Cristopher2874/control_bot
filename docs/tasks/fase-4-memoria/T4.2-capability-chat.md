# T4.2: Capability chat con memoria

- **Fase:** 4
- **Estado:** Pendiente
- **Depende de:** T4.1

## Objetivo

`harness chat` mantiene conversaciones entre ejecuciones y arma el contexto respetando la política de privacidad. Cierra la Fase 4.

## Contexto mínimo

- **Chat es una capability** (`packages/capabilities/chat/`), igual que computer use: manifest, entry point y un workflow `conversar`. No tiene tools en esta tarea.
- **Armado de contexto:** system prompt + los últimos N mensajes de la conversación que quepan en el `num_ctx` del perfil (estimación simple: ~4 caracteres por token) + el mensaje nuevo. Si el historial trae mensajes `private`, el run se contamina (T4.1) y va a local.
- **Comandos:**
  - `harness chat "texto"` continúa la última conversación.
  - `harness chat --new "texto"` empieza otra.
  - `harness chat --conv <id> "texto"` continúa una concreta.
  - `harness chats` lista las recientes (id, título, fecha).
- **Título** de la conversación: los primeros ~40 caracteres del primer mensaje. Sin LLM.
- Al terminar el turno se guardan el mensaje del usuario y la respuesta con la sensibilidad final del run.

## Alcance

**Incluye:** capability `chat`, armado de contexto, cambios en la CLI.

**Fuera de alcance:** recuperar hechos de otras conversaciones, búsqueda, resúmenes automáticos.

## Tests mínimos

- `test_chat_memory.py::test_contexto_recorta_por_presupuesto`: un historial largo se recorta a lo que cabe, conservando los mensajes más recientes.
- `test_chat_memory.py::test_historial_privado_va_a_local`: conversación con un mensaje `private` + pregunta que sería pública y pesada → el `FakeProvider` recibe un perfil local.
- `test_chat_memory.py::test_conversacion_real` (`@pytest.mark.ollama`): dos turnos, el segundo usa información del primero.
