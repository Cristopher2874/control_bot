# T5.2: Adaptador de Telegram

- **Fase:** 5
- **Estado:** Pendiente
- **Depende de:** T5.1

## Objetivo

Lo mismo que la CLI funciona desde el celular: un bot de Telegram delgado sobre el runtime, con confirmaciones por botones y solo para usuarios autorizados. Cierra la Fase 5.

## Contexto mínimo

- **Adaptador delgado:** `apps/telegram` solo traduce mensajes a jobs (T5.1) y eventos a mensajes. Ninguna lógica de negocio, ningún tipo de Telegram fuera de `apps/telegram`.
- **Comandos:** texto libre → chat. `/run <texto>` → workflow o agente. `/stop` → cancela el job en curso. `/new` → conversación nueva. `/dry <texto>` → run en dry-run.
- **Confirmaciones:** `confirmation_requested` → mensaje con botones Sí/No (inline keyboard) → `answer_confirmation`.
- **Formato:** rescatar `telegram_markdown` de `legacy/` para escapar la salida a MarkdownV2.
- **Librería:** `python-telegram-bot` (la que ya usaba el bot viejo).
- **Token y allowlist** desde el entorno (`HARNESS_TELEGRAM_TOKEN`, `HARNESS_TELEGRAM_ALLOWED_USERS`). Mensajes de usuarios fuera de la allowlist se ignoran sin responder.

## Alcance

**Incluye:** `apps/telegram` con los comandos de arriba, botones de confirmación, allowlist, formato.

**Fuera de alcance:** voz, archivos adjuntos, varios usuarios con memorias separadas.

## Pasos de implementación

1. Composition root propio: `build_app()` + runtime + bot.
2. Handlers de comandos → `submit`.
3. Suscriptor de eventos → mensajes y botones.
4. Allowlist como primer filtro de cada update.

## Output esperado

Desde el celular: "abre spotify" → el bot muestra los pasos y el resultado. `/run` con un script `dangerous` → botones Sí/No.

## Criterios de aceptación

- [ ] Chat, run, stop y confirmaciones funcionan desde Telegram.
- [ ] Solo responde a usuarios de la allowlist.
- [ ] `harness` (núcleo) no depende de `python-telegram-bot`.
- [ ] Marcar la Fase 5 en `docs/roadmap.md`.

## Telemetría

- `job_started` incluye `origin: telegram`. Nunca registrar el token ni el `chat_id` completo (solo un hash corto).

## Seguridad

- **Telegram es un servicio externo:** todo lo que el bot responde pasa por sus servidores, aunque el modelo haya corrido en local. La salida de un run `private` sale de la máquina al mandarla al chat.
- Token solo por entorno. Allowlist obligatoria: sin ella el bot no arranca.

## Decisiones abiertas

- **Respuestas privadas por Telegram:** ¿se mandan completas, se mandan resumidas ("listo, 2 acciones ejecutadas") o se piden con una confirmación extra? Propuesta: para runs `private`, mandar solo el estado y las acciones (sin el contenido devuelto por las tools), con un comando `/ver` para pedir el detalle conscientemente.
