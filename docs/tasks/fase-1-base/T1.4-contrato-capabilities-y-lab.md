# T1.4: Contrato de capabilities y lab

- **Fase:** 1
- **Estado:** Pendiente
- **Depende de:** T1.2 (y T1.3 para el flag `--lab` y el sandbox)

## Objetivo

Existe el contrato de capabilities (manifest en YAML, descubrimiento por entry points, registry que valida) sin ninguna capability real, y `lab/sandbox.py` deja listos los recursos del harness en una línea.

## Contexto mínimo

- **Una capability** es un paquete Python con un `capability.yaml` (manifest), sus tools, sus workflows y sus drivers. En esta tarea solo existe el manifest y el registry.
- **Descubrimiento por entry points** (decisión del usuario, 2026-11-21): cada capability se registra en el grupo `harness.capabilities` de su `pyproject.toml`. El entry point apunta al paquete. El registry lee el `capability.yaml` que está junto a él.
- **Manifest en YAML** (decisión del usuario): se valida y se convierte a un modelo Pydantic `Manifest`. Formato:

  ```yaml
  name: computer_use
  version: 0.1.0
  channel: stable            # stable | lab
  data_sensitivity: private  # private | public: sensibilidad de lo que devuelven sus tools
  tools:
    list_windows: { permission: read }      # read | act | dangerous
    open_app:     { permission: act }
  limits:
    max_actions_per_run: 20
  ```

- **El registry** recibe los entry points (inyectables para tests), carga y valida cada manifest, rechaza nombres duplicados y tools sin `permission`, y solo incluye las de `channel: lab` si se le pasa `include_lab=True`.
- **Lab:** `lab/` no es paquete del workspace. `lab/sandbox.py` expone `sandbox()` que llama a `build_app()` (T1.3) y devuelve el `App` listo para scripts de experimentos. **Producción nunca importa de `lab/`.**
- **`--lab`:** opción global de la CLI que se pasa a `build_app(include_lab=True)`. Sin capabilities todavía, solo cambia qué carga el registry.

## Pasos de implementación

1. `Manifest` y `ToolSpec` en Pydantic con enums para `channel`, `permission` y `data_sensitivity`.
2. `discover(entry_points=None) -> list[Manifest]`: por defecto usa `importlib.metadata.entry_points(group="harness.capabilities")`.
3. `Registry(manifests, include_lab)`: valida y expone `capabilities()` y `manifest(name)`.
4. `build_app(include_lab=False)` construye el registry. `harness --lab chat ...` lo activa.
5. Plantilla de experimento con las secciones: Estado, Hipótesis, Cómo se prueba, Resultados, Decisión.
6. ADR-0007 con la plantilla de `docs/decisions/0000-plantilla.md`. En `capabilities.md`, reemplaza la sección "Preguntas abiertas" por un enlace al ADR.

## Output esperado

- `uv run harness --lab chat "hola"` funciona igual que sin `--lab`.
- `uv run python lab/sandbox.py` imprime los perfiles disponibles y las capabilities cargadas (lista vacía).

## Tests mínimos

- `test_registry.py::test_manifest_valido_y_lab_filtrado`: dos manifests falsos (uno `stable`, uno `lab`); sin `include_lab` solo aparece el estable, con `include_lab` aparecen los dos.
- `test_registry.py::test_manifest_invalido`: tool sin `permission` o nombre duplicado → error con el nombre de la capability.
- `test_registry.py::test_produccion_no_importa_lab`: recorre los `.py` de `packages/` y `apps/` y falla si alguno importa `lab`.
