# T1.1: Workspace, legacy y tooling

- **Fase:** 1
- **Estado:** En revisión
- **Depende de:** —

## Objetivo

El código del bot anterior queda en `legacy/` y la raíz es un workspace de uv vacío pero funcional, con ruff, pyright y pytest configurados.

## Contexto mínimo

- El proyecto se reinicia desde cero como harness. El código viejo se conserva en `legacy/` solo para rescatar piezas; nadie lo importa ni lo ejecuta.
- Workspace de uv con tres miembros: `packages/harness` (librería, import `harness`), `apps/cli` (comando `harness`) y el lab, que no es paquete (scripts sueltos en `lab/`).
- Layout `src/`: `packages/harness/src/harness/`, `apps/cli/src/harness_cli/`. Evita imports accidentales desde la raíz.
- Python `>=3.13` (el mismo del proyecto actual).
- Los tests viven en `tests/` en la raíz y no necesitan Ollama.

## Alcance

**Incluye:**
- Mover a `legacy/` con `git mv`: `app/`, `lab/` (el viejo), `main.py`, `mcps/`, `tests/` (el viejo), `response.json`.
- Nuevo `pyproject.toml` raíz como workspace, con dependencias de desarrollo y la configuración de las herramientas.
- Esqueletos vacíos de `packages/harness` y `apps/cli` (solo `pyproject.toml` y `__init__.py`).
- `.gitignore` actualizado y un `README.md` raíz nuevo.

**Fuera de alcance:**
- Cualquier código del harness (es T1.2 y siguientes).
- Arreglar o borrar código de `legacy/`.

## Pasos de implementación

1. `git mv` de lo listado a `legacy/`. Crea `legacy/README.md` con una línea: "Código del bot anterior. Solo referencia; se borra en T5.3."
2. `pyproject.toml` raíz:
   - `[tool.uv.workspace] members = ["packages/harness", "apps/cli"]`.
   - Grupo dev: `pytest`, `ruff`, `pyright`.
   - `[tool.ruff]`: `line-length = 100`, reglas `E, F, I, UP, B`. Excluir `legacy/`.
   - `[tool.pyright]`: `typeCheckingMode = "standard"`, `include = ["packages", "apps", "lab"]`, excluir `legacy/`.
   - `[tool.pytest.ini_options]`: `testpaths = ["tests"]`, marcador `ollama` registrado y excluido por defecto (`addopts = "-m 'not ollama'"`).
3. `packages/harness/pyproject.toml` y `apps/cli/pyproject.toml` con build backend de uv (`uv_build`), sin dependencias todavía. `apps/cli` depende de `harness` como fuente de workspace.
4. `.gitignore`: agregar `.harness/` (trazas y datos locales), `.venv/`, `__pycache__/`, `.env`. Revisar que `legacy/` sí se versione.
5. `README.md` raíz: qué es el harness (3 o 4 líneas), cómo instalar (`uv sync`), el comando objetivo de la Fase 1 y enlaces a `docs/tasks/README.md` y `docs/architecture/overview.md`. Corto.
6. `uv sync` para regenerar `uv.lock` (se permite correrlo).
